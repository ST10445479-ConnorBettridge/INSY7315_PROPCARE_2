## Fixes covered by the checks

Refresh-token races and stale-cookie logout, failed sign-out feedback, request paging, report grouping, tenancy constraints, password byte limits, photo-loading errors, colour contrast, keyboard dialogs and report-form loading were corrected and checked.

A separate local load exercise added 1,000 properties and 10,000 requests. With eight concurrent clients, 160 reads and 40 creates completed without errors; the 95th-percentile response time was 36 ms. This measures local performance, not cloud capacity.

## Remaining checks and limits

Manual screen-reader testing, Safari/physical Android testing, first-time-user timing, long-duration cloud load tests and long-term uptime remain unverified. Automated accessibility scans do not establish full WCAG conformance. The free hosting setup does not demonstrate the Part 1 targets of 99% business-hours uptime or operation at 5,000-property scale.

In-app notifications and administrator password resets are implemented. Email/SMS delivery, email-based password recovery and malware scanning are not implemented. See [requirements](REQUIREMENTS.md) and [deployment](DEPLOYMENT.md) for the implemented scope.

## Running the checks

The [README](../README.md#tests) covers API and browser tests. `npm run audit:infrastructure` additionally checks publishing, database constraints, local load and backup restoration. It requires PostgreSQL tools and permission to create separate audit databases. `node scripts/container-smoke.mjs` runs the Docker persistence checks.

Local logs and results are stored in ignored `.local/` and `test-results/` directories. CI results are available in GitHub Actions.
